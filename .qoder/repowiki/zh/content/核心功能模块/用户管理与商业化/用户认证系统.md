## 简介

QuantDinger的用户认证系统是一个基于Flask的多用户认证平台，支持多种登录方式和安全机制。该系统实现了JWT令牌认证、密码哈希、双重登录控制、验证码验证等功能，为用户提供安全可靠的访问控制。

系统主要特点：
- 支持用户名和邮箱双重登录方式
- 使用bcrypt优先的密码哈希算法
- 实现单一客户端登录控制（踢出其他设备）
- 提供多种认证方式（密码登录、验证码登录、OAuth）
- 具备完善的安全防护机制
- **新增**：验证码发送端点(/api/auth/send-code)和密码修改端点(/api/auth/change-password)
- **新增**：增强的验证码系统，包含速率限制、IP追踪、Turnstile验证

### 密码哈希机制

系统实现了双层密码哈希策略：

```mermaid
flowchart TD
Start([密码输入]) --> CheckBCrypt{bcrypt可用?}
CheckBCrypt --> |是| UseBCrypt[使用bcrypt哈希<br/>成本因子12]
CheckBCrypt --> |否| UseSHA256[使用SHA256哈希<br/>带盐值]
UseBCrypt --> BCryptSalt[生成12轮盐值]
BCryptSalt --> BCryptHash[bcrypt.hashpw]
UseSHA256 --> SHA256Salt[生成16字节随机盐]
SHA256Salt --> SHA256Hash[sha256(密码+盐)]
BCryptHash --> Store[存储哈希值]
SHA256Hash --> Store
Store --> Verify[验证密码]
Verify --> VerifyBCrypt{bcrypt哈希?}
VerifyBCrypt --> |是| BCryptVerify[bcrypt.checkpw]
VerifyBCrypt --> |否| SHA256Verify[sha256(密码+盐)比较]
BCryptVerify --> Success[验证成功]
SHA256Verify --> Success
```

## 验证码增强系统

### 验证码发送端点

新增的验证码发送端点(/api/auth/send-code)提供了灵活的验证码发送功能：

#### 端点特性

| 特性 | 描述 |
|------|------|
| **验证码类型** | register, login, reset_password, change_password, change_email |
| **Turnstile验证** | 除change_password外均需验证 |
| **速率限制** | 邮箱每分钟1次，IP每小时10次 |
| **邮箱验证** | 验证邮箱格式有效性 |
| **安全日志** | 记录验证码发送事件 |

#### 验证码类型说明

| 类型 | 用途 | Turnstile验证 | 邮箱检查 |
|------|------|---------------|----------|
| register | 用户注册 | 必需 | 邮箱必须未注册 |
| login | 快速登录 | 必需 | 可选 |
| reset_password | 重置密码 | 必需 | 可选（但不泄露邮箱存在） |
| change_password | 修改密码 | **可选**（已登录用户） | 必需 |
| change_email | 更改邮箱 | 必需 | 必需 |

#### 验证码发送流程

```mermaid
flowchart TD
Start([发送验证码请求]) --> ValidateInput[验证输入参数]
ValidateInput --> CheckType{验证码类型}
CheckType --> |change_password| CheckAuth[检查用户认证]
CheckAuth --> SkipTurnstile{已登录?}
SkipTurnstile --> |是| SkipTurnstileCheck[跳过Turnstile验证]
SkipTurnstile --> |否| CheckTurnstile[验证Turnstile]
CheckTurnstile --> CheckRateLimit[检查发送频率限制]
SkipTurnstileCheck --> CheckRateLimit
CheckRateLimit --> RateAllowed{允许发送?}
RateAllowed --> |否| ReturnRateLimit[返回429错误]
RateAllowed --> |是| ProcessType[处理不同类型]
ProcessType --> RegisterType[register类型]
RegisterType --> CheckEmailUnique[检查邮箱唯一性]
CheckEmailUnique --> SendCode[发送验证码]
ProcessType --> ResetType[reset_password类型]
ResetType --> CheckEmailExists[检查邮箱存在]
CheckEmailExists --> SendCode
ProcessType --> ChangeType[change_password类型]
ChangeType --> SendCode
ProcessType --> OtherType[其他类型]
OtherType --> SendCode
SendCode --> LogEvent[记录安全事件]
LogEvent --> Success[返回成功]
```

## 性能考虑

### 缓存策略

系统采用了多层次的缓存策略来提升性能：

1. **数据库连接池**：使用PostgreSQL连接池减少连接开销
2. **内存缓存**：用户信息在内存中缓存，减少数据库查询
3. **令牌缓存**：JWT令牌验证结果可以进行短期缓存
4. **验证码缓存**：验证码验证结果可以进行短期缓存

### 性能优化建议

1. **索引优化**：确保用户表和验证码表的关键字段有适当的索引
2. **批量操作**：对于大量用户操作，使用批量处理
3. **异步处理**：将非关键的后台任务异步化
4. **连接复用**：合理管理数据库连接，避免频繁创建销毁
5. **验证码清理**：定期清理过期的验证码记录

## 故障排除指南

### 常见问题及解决方案

#### 1. bcrypt安装问题

**问题**：系统提示bcrypt不可用
**解决方案**：
- 安装bcrypt依赖：`pip install bcrypt`
- 或者使用SHA256作为回退方案

#### 2. JWT令牌验证失败

**问题**：令牌验证总是失败
**解决方案**：
- 检查SECRET_KEY配置是否正确
- 确认令牌未过期
- 验证token_version是否匹配

#### 3. 登录频繁被限制

**问题**：登录尝试被限制
**解决方案**：
- 检查IP地址是否被标记为恶意
- 等待冷却时间结束
- 联系管理员解除限制

#### 4. 验证码发送失败

**问题**：验证码无法发送
**解决方案**：
- 检查邮件服务配置
- 验证发送频率限制
- 确认邮箱格式正确
- 检查Turnstile配置

#### 5. 验证码验证失败

**问题**：验证码无法验证
**解决方案**：
- 检查验证码是否过期
- 确认验证码类型正确
- 验证尝试次数限制
- 检查数据库连接

#### 6. 密码修改失败

**问题**：密码修改请求失败
**解决方案**：
- 检查验证码是否有效
- 确认新密码符合长度要求
- 验证用户是否已登录
- 检查数据库事务
